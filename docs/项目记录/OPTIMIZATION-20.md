# 工作台优化 20 条：从"能用"到"作品"

> 对象：`workbench/`（MindWeave 原版前端 + 真实后端 + Docker 数据库 + MindWeave Harness 工具能力）
> 标准：不是"功能齐全"，而是**默认正确、反馈及时、可解释、可恢复、有品味**。
> 每条给：现状 → 做法 → 验收指标 → 成本（人天）。

---

## 先立四条"作品级"原则

1. **默认正确**：安全、隐私、失败处理不靠用户勾选。
2. **感知性能**：首字 1.5s 内出现，剩余用骨架/流式补齐。
3. **可解释**：每个结论能点回原文，每一步能看轨迹。
4. **可恢复**：断网、崩溃、误操作都能回到上一状态。

---

## A. 对话与检索（1–7）

### 1. 首字延迟预算（TTFT）
- **现状**：检索 + 模型首 token 前，界面只有转圈；冷启动时可达 10s+。
- **做法**：先推 `thinking` 事件占位（已有），再加"正在检索 3 个来源"的骨架卡片；模型侧启用流式（已开），检索侧先返回"部分证据"再补全。
- **验收**：P50 TTFT < 1.5s，P95 < 4s；骨架在 200ms 内出现。
- **成本**：2 天。

### 2. 引用可点击、可回跳
- **现状**：回答里的 `[1]` 是纯文本；用户无法核对。
- **做法**：后端在 `sources` 里带 `doc_id + chunk_id + page`；前端把 `[n]` 渲染成链接，点击打开文档抽屉并**高亮对应切片**。
- **验收**：任意引用点击后 500ms 内定位到原文段落；引用捏造数 = 0。
- **成本**：3 天。

### 3. 答案结构契约
- **现状**：模型有时给"结论/要点"，有时一大段。
- **做法**：系统提示固定四段（结论 / 要点 / 依据 / 边界），前端按段渲染；缺段时提示"未给出边界"。
- **验收**：抽样 50 条回答，结构合规率 ≥95%。
- **成本**：1 天。

### 4. 检索质量：混合 + 重排 + 多样性
- **现状**：MindWeave 已有 hybrid/graph/rerank 代码，但重排依赖模型分级，冷启动慢；图谱未完全建好。
- **做法**：检索 Top20 → 模型重排（批量一次）→ 同文档限 2 条；低分片段直接丢弃；空结果明确说"没找到"而不是硬凑。
- **验收**：自带 6 题 Recall@3 ≥ 5/6；引用捏造 0；P95 检索 < 2s。
- **成本**：4 天。

### 5. 失败态设计（超时/限流/无权限）
- **现状**：超时抛一句"本轮处理超时"。
- **做法**：区分"检索超时 / 模型超时 / 权限拒绝"，各给可操作按钮（重试、换问法、申请权限）；错误码写进 trace。
- **验收**：每种失败都有明确的下一步；错误率可按类型统计。
- **成本**：2 天。

### 6. 断线续跑（MindWeave Harness 三态）
- **现状**：MindWeave 有 run/checkpoint，但没有"未闭合工具三态"。
- **做法**：把 MindWeave Harness 的 `not_started / safe_to_retry / verify_before_retry` 接进 `run_store`；断线后恢复时按三态补回执。
- **验收**：kill -9 后继续，写操作不重复、只读可安全重试。
- **成本**：5 天。

### 7. 审批体验
- **现状**：单条批准/拒绝，无批量、无超时提示、无审计列表。
- **做法**：支持"本次会话都允许此类操作"（按工具+范围）、审批超时倒计时、审批历史可查；拒绝理由可回填给模型。
- **验收**：重复审批下降 50%；每次审批可追溯到 run/工具/参数。
- **成本**：3 天。

## B. 知识库与图谱（8–12）

### 8. 导入体验
- **现状**：上传有进度，但失败原因弱、断点无、批量无摘要。
- **做法**：拖拽 + 逐文件状态 + 失败重试 + "本次导入 N 成功 M 失败"汇总；大文件后台处理，页面可离开。
- **验收**：10 个文件导入成功率 ≥98%；失败可单条重试。
- **成本**：3 天。

### 9. 文档详情：目录 + 切片高亮 + 页码
- **现状**：详情只渲染正文；切片列表与原文不联动。
- **做法**：左侧目录、右侧正文；点切片滚动并高亮；PDF 显示页码与页面图。
- **验收**：从回答引用一键定位到"文档 › 章节 › 片段"。
- **成本**：4 天。

### 10. 知识库健康度
- **现状**：文档状态有 completed，但没有"索引失败/图谱未建"的体检。
- **做法**：加"健康检查"页：孤儿切片、失败任务、重复 MD5、未建图谱的文档、过期索引；一键重建。
- **验收**：任意文档能看到"切片数 / 向量状态 / 图谱状态"。
- **成本**：3 天。

### 11. 图谱可用化
- **现状**：图谱页数据依赖 worker，冷启动时空白。
- **做法**：空态给出"正在构建，预计 X 分钟"；实体点击联动相关笔记；支持按类型筛选。
- **验收**：导入 5 篇文档后 2 分钟内能看到实体与关系。
- **成本**：4 天。

### 12. 检索可解释
- **现状**：用户不知道"为什么这条被选中"。
- **做法**：证据卡片展示来源、章节、分数、重排等级；"为什么没检索到"给查询改写建议。
- **验收**：每条证据都能说清来源与分数。
- **成本**：2 天。

## C. 工程与性能（13–17）

### 13. 首屏与包体
- **现状**：前端单包，图谱/编辑器库重。
- **做法**：路由级 code split（图谱、编辑器、设置懒加载）；首屏预加载对话与知识库。
- **验收**：首屏 JS < 300KB gzip；LCP < 2s。
- **成本**：3 天。

### 14. 缓存与预取
- **现状**：会话/文档每次全量拉。
- **做法**：会话列表 SWR、文档详情本地缓存、检索结果按 query 短期缓存；上传后局部刷新。
- **验收**：二次打开会话 < 300ms；重复检索命中缓存。
- **成本**：2 天。

### 15. 可观测性
- **现状**：有 trace 表，但缺 P95/错误率面板。
- **做法**：统一 span（检索/模型/工具/审批）；暴露 `/metrics`；每日汇总慢查询与失败 Top10。
- **验收**：任一慢请求能定位到具体 span；错误率可按工具统计。
- **成本**：3 天。

### 16. 配额与成本
- **现状**：无 token 用量展示。
- **做法**：每次对话记录 input/output token；用户页显示"本月用量/剩余"；超限降级到检索摘要。
- **验收**：用量与账单误差 <5%；超限行为明确。
- **成本**：2 天。

### 17. 一致性与幂等
- **现状**：审批、导入、图谱任务各有状态机，恢复语义不统一。
- **做法**：统一 `run_id + idempotency_key`；写操作只执行一次；失败任务可重放。
- **验收**：重复点击/断线重试不产生重复写入。
- **成本**：5 天。

---

## D. 信任、无障碍与品味（18–20）

### 18. 隐私与数据控制
- **现状**：没有导出/彻底删除入口。
- **做法**：一键导出（笔记+文档+会话）；删除即删切片/向量/图谱；隐私说明写清"哪些会发给模型"。
- **验收**：导出包含全部用户数据；删除后检索不到残留。
- **成本**：3 天。

### 19. 无障碍与键盘
- **现状**：只有鼠标操作，焦点态弱。
- **做法**：全键盘可达（Tab/Enter/Esc）、快捷键（⌘K 搜索、⌘Enter 发送）、对比度 ≥4.5:1、暗色对齐。
- **验收**：纯键盘完成"提问→审批→查看引用"。
- **成本**：3 天。

### 20. 品牌与细节
- **现状**：空态、加载态、错误文案偏工程化。
- **做法**：统一的空态插画与一句人话；动效 150–250ms；文案去掉"接口/参数"；品牌色只用于强调。
- **验收**：随机截 10 个界面，文案无术语、无重复 loading。
- **成本**：2 天。

## 优先级与路线

| 批次 | 内容 | 目标 |
|---|---|---|
| **第 1 周** | 1、2、5、8 | 首字快、引用可点、失败可懂、导入可用 |
| **第 2 周** | 3、4、9、12 | 答案稳、检索准、原文可定位 |
| **第 3 周** | 6、7、17 | 断线能续、审批省心、写入不重复 |
| **第 4 周** | 10、11、15、16 | 知识库体检、图谱可用、可观测、成本可见 |
| **第 5 周** | 13、14、18、19、20 | 首屏、缓存、隐私、键盘、品味 |

| 断线恢复成功率 | 100% |

| 首屏 LCP | < 2s |

## 不做什么（避免过度设计）

- 不做多租户/团队协作（当前单用户已够）；
- 不做自研向量库（Neo4j 够用）；
- 不做插件市场（先把 3 个核心工具打磨好）；
- 不做移动端原生（响应式即可）。
