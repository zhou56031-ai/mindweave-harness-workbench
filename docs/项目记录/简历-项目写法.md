## 二、直接可用的版本（5 条，已验证）

> 智能文档工作台（MindWeave × MindWeave Harness） ｜ 2026.07 – 至今
>
> 面向个人知识库的智能工作台：前端沿用 MindWeave（React 19 + Vite），后端 FastAPI + MySQL/Redis/Neo4j，接入 MindWeave Harness 的运行时能力（工具、审批、恢复、预算），把"检索—对话—写文件—执行代码"串成一条可恢复的链路。
>
> **技术栈**：Python 3.12、FastAPI、MySQL、Redis、Neo4j、React 19、Vite、SSE、Docker

- **可恢复的 Agent 运行时**：针对审批执行中途崩溃后"不知道写没写"的问题，把 MindWeave Harness 的恢复语义接进工作台——启动时把超时 `executing` 标记为 `needs_verification`，恢复时拒绝自动重试并要求人工核对；重复审批返回"没有可恢复的审批"，实测文件数 1→1，不产生重复写入。

- **工具调用与审批管线**：为 Agent 接入 `write_file` / `read_file` / `list_files` / `run_python` / `plan` 五类工具；写操作统一走人工审批，支持"本会话都允许"（1h）与 30 分钟过期，文件路径限制在个人工作区（防 `../` 穿越）；实测"申请 → 审批 → 落盘 → 回读"闭环，生成文件内容与请求一致。

- **知识库与检索决策**：导入 117 篇文档、2,770 个切片；对"混合检索 / 加 LLM 重排 / 完整证据链"做 6 题 A/B：Recall@3 均为 50%，平均延迟 594 / 1,276 / 5,681 ms——据此新增 `RERANK_ENABLED` 开关，而不是默认打开重排。

- **首字延迟优化**：针对首字 11.3s 的问题，改为"预检索 + 直接流式作答"，省掉一轮"决定是否检索"的模型调用；TTFT 降到 **P50 ≈ 6.3s（5.6/6.3/6.3/7.0/13.1）**，并在 `done` 事件埋点 `ttft_ms` 持续观测；最差 13.1s 为流式失败回退，如实记录。

- **工程化与可观测**：新增 `/metrics`（请求数/错误率/平均耗时/最慢路径）、`/user/export`（33KB 全量导出，笔记 1/文档 117/会话 9/消息 18）、`/knowledge/health`（117 篇/2,770 片/healthy）、`/chat/approvals` 审批审计；20 项优化逐条验证，`tsc` 0 错误、`vite build` 通过、接口级 curl 断言。

## 六、写之前先问自己三个问题

1. **这条能演示吗？** 不能演示的，降到"了解"或删掉。
2. **数字有条件吗？** 延迟要写模型、机器、样本量；不然一追问就崩。
3. **失败案例有吗？** 每条最好配一个"我们试过但没采用"的决策（重排就是最好的例子）。
